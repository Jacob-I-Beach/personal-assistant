## User-facing changes

- Separate public progress updates, persistent web activity, one action row after the final answer, readable JavaScript results and native mathematical rendering. No private reasoning transcript is displayed.
- More than three unique cited source URLs use an initially collapsed source list. Duplicate annotations share a row while retaining each inline reference number.
- New chats receive topic names generated by the selected model after a successful answer. Manual names are preserved. Naming is a bounded metadata request with no hosted tools; verified GPT-6 models use low effort for this metadata. Users can disable automatic titles.
- Photo library presentation is owned by the persistent chat view rather than the transient attachment menu.
- GPT reasoning control appears beside the composer controls. Low, Medium, High, Extra High and Max map to the provider's exact effort values. Choices persist per model and do not invalidate its provider continuation. Published account capabilities override the verified fallback list.
- Generated text artifacts and PDFs receive a verified, collision-safe copy in Documents/Outputs, visible in Files. The private Library original remains available. External edits to a Files copy are not silently overwritten or imported into the original.
- Library and artifact views expose native Save to Files actions. An assistant export tool reports the picker-confirmed outcome, including cancellation, without claiming that cloud sync has finished.
- Connected folders have persistent iOS bookmarks, per-chat selection, separate connected-model sharing and editing controls, browsing, bounded reading/search, and metadata inspection.
- New files can be created in a selected root or listed subfolder. Existing text files use a saved version, a native diff review, a current-content check, and verified saving. Original/revised snapshots remain inspectable in edit history. Cancelled proposals cannot be applied.
- A concise capability query reports actual app tools, their review requirements and runtime limits. The 260-word base instructions focus on useful work, natural communication, evidence and reliable outcomes; detailed schemas stay in the tool layer.

## Boundaries and reuse

The existing orchestration loop, checkpoints, SQLite history, memory controls, JavaScript sandbox, PDF writer, original-file Library, native composers and provider adapters remain the foundation.

The connected-folder iteration supports UTF-8 replacement up to 128 KB and 2,000 lines, after review. It does not rewrite binary Office/PDF formats, delete folders, bulk-move files or launch a desktop terminal. Search is explicitly bounded to 1,000 entries, 30 matches, 2 MB of text, and a 32 KB prefix per text file. Hidden files and links are excluded. Provider availability and synchronization remain outside the app's guarantees.

The existing PDF tool creates genuine paginated documents and verifies them by reopening with PDFKit; it now returns page count. It retains its documented basic-text-layout limit.

The brief's share extension, broader native integrations, continued-background-task scheduling and remote developer workspace are later capabilities, not advertised by this batch. No cloud execution service or new paid model service was provisioned.
