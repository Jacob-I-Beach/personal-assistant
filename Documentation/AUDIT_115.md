## Memory provisioning

Apple's regular `com.apple.developer.kernel.increased-memory-limit` is distinct from debugging-memory and extended-addressing capabilities. The Standard package requests no entitlements. A separate Memory signing input requests only the regular memory entitlement, with identical compiled code and Health/push still disabled. It is **not** a provisioned or installed memory grant.

[Apple's entitlement documentation](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.kernel.increased-memory-limit) describes supported-device behavior and requires runtime checks. [AltSign's capability implementation](https://github.com/rileytestut/AltSign/commit/b2c88617932905b13e42f1dd0d8b1d45d26cf671) and a [recent SideStore issue](https://github.com/SideStore/SideStore/issues/1616) provide evidence of a free-account route. The latter reports roughly 3.3 versus 6 GB on its author's phone; it is not this user's measured allowance or proof that the current Sideloadly flow preserves the capability. Final signing/profile contents and actual headroom must be verified. Do not require paid enrollment solely on the assumption that all memory entitlements are paid-only.
